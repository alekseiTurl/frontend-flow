# Установка и настройка

## Требования

- Codex с поддержкой пользовательских агентов, навыков, MCP и lifecycle hooks.
- Доступ к моделям из [таблицы ролей](frontend-flow.md). Доступность зависит от аккаунта и клиента; установщик её не проверяет.
- Python 3.11 или новее; сторонние Python-пакеты не нужны.
- Node.js 22 или новее и `npx` в PATH. Node нужен хуку и проверкам flow; npx — Playwright MCP.
- Для UI-проверок: запускаемый проект, его зависимости, доступные браузер и безопасные тестовые данные.

## Установка

Клонируйте репозиторий:

```sh
git clone https://github.com/alekseiTurl/frontend-flow.git
cd frontend-flow
```

В Windows используйте `python` или `py -3`; на macOS/Linux обычно `python3`. В примерах ниже используется `python`.

Посмотрите запланированные изменения:

```sh
python scripts/install.py --dry-run --configure-playwright
```

Установите:

```sh
python scripts/install.py --configure-playwright
```

Каталог назначения — `CODEX_HOME`, если он задан, иначе `~/.codex`. Для другого каталога:

```sh
python scripts/install.py --codex-home "/path/to/.codex" --configure-playwright
```

Установщик копирует агентов и оба навыка, добавляет хук в `hooks.json` и формирует команду с абсолютным путём для этого компьютера. Существующие сторонние хуки и настройки сохраняются. Совпадающие файлы не переписываются. При конфликте файлов комплект останавливается до записи; после проверки различий разрешите обновление:

```sh
python scripts/install.py --overwrite --configure-playwright
```

Изменяемые существующие файлы сохраняются в `<CODEX_HOME>/frontend-flow-backups/<timestamp>/`. Не публикуйте эту папку: резервные копии конфигурации могут содержать личные настройки. Для отката закройте активные задачи и восстановите нужные файлы из соответствующей копии. Новые файлы без предыдущей версии в резервную копию не входят.

Флаг `--configure-playwright` добавляет пример конфигурации только при отсутствии `mcp_servers.playwright`. Существующий сервер сохраняется без изменений. Без этого флага настройте сервер по [примеру](../config/playwright.toml) вручную. Пример использует `@playwright/mcp@latest`; для воспроизводимого окружения зафиксируйте проверенную вами версию пакета.

Откройте Codex, просмотрите и разрешите новый хук через `/hooks` в CLI, затем начните новый чат. Установщик не меняет доверие к хукам, sandbox или разрешения. Если найден другой хук frontend-flow, объедините определения вручную, чтобы избежать двойного запуска. Официальные сведения: [hooks](https://learn.chatgpt.com/docs/hooks), [пользовательские агенты](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Установка не запускает MCP-сервер и не загружает браузеры. При первом UI-задании проверьте доступность инструментов Playwright MCP в Codex. Если сервер, браузер или приложение недоступны, flow честно отмечает проверку как `blocked`.

## Правила ответов

Краткие ответы на русском уже включены во все роли flow. Если хотите применять эти правила ко всем задачам Codex, используйте:

```sh
python scripts/install.py --install-style
```

Установщик добавляет отдельный отмеченный блок в пользовательский `AGENTS.md` и сохраняет остальные инструкции. [Исходный текст правил](../instructions/AGENTS.md).

## Настройка комплекта

Модели, effort и состав инструкций задаются в [agents/roles.json](../agents/roles.json), правила процесса — в [SKILL.md](../skills/frontend-flow/SKILL.md), инструкции ролей — в [references](../skills/frontend-flow/references).

После изменения ролей выполните `python scripts/generate_agents.py`. При смене моделей обновите таблицы в `SKILL.md`, `README.md` и `docs/frontend-flow.md`, а также заголовки и маршрутизацию ролевых references. Недоступная модель автоматически не подменяется: выберите доступную и явно обновите конфигурацию.

Системный навык Codex `skill-creator` нужен только для редактирования навыков через Codex; он не является runtime-зависимостью flow и не копируется в комплект.

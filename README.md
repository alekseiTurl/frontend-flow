# Frontend flow для Codex

Комплект агентов и навыков для frontend-разработки: согласованный план, реализация, проверка UI через Playwright MCP, независимое ревью, исправления и тексты коммита/MR.

`@FF` запускает полный процесс. `@FW` вызывает только автора коммита/MR. Подробности — в [инструкции](docs/frontend-flow.md).

## Состав

- 8 агентов: архитектор, Junior Dev, Middle Dev, Senior Dev, багфиксер, тестировщик, ревьюер и writer.
- Навык `frontend-flow` и обязательный для ревьюера навык `code-review`.
- Хук `SessionStart`: напоминает о сохранённом состоянии `.frontend-flow` при начале, возобновлении и сжатии сессии.
- Проверки согласованного плана и завершения: `check-plan`, `check-done`.
- Конфигурация Playwright MCP, необязательные глобальные правила ответов и установщик.
- Тесты установщика, хука и проверки завершения; GitHub Actions для Windows, macOS и Linux.

| Агент | Модель / усилие | Задача |
| --- | --- | --- |
| Архитектор (`frontend_architect`) | `gpt-6.1-sol / medium` | Уточняет требования, готовит план и проверки, выбирает исполнителя |
| **Junior Dev** (`junior_dev`) | `gpt-5.6-luna / medium` | Простые рутинные правки по готовому образцу |
| **Middle Dev** (`middle_dev`) | `gpt-5.6-terra / medium` | Локальная логика, взаимодействие компонентов, типовые формы и состояния |
| **Senior Dev** (`senior_dev`) | `gpt-5.6-sol / high` | Сложная логика, связи модулей, async, SSR |
| Багфиксер (`frontend_bugfixer`) | `gpt-5.6-sol / high` | Воспроизводит дефекты, устраняет причину, запускает проверки |
| Тестировщик (`frontend_tester`) | `gpt-5.6-terra / high` | Запускает приложение и проверяет изменённый UI через Playwright MCP |
| Ревьюер (`frontend_reviewer`) | `gpt-6.1-sol / high` | Проверяет выполнение требований, качество кода и исправления |
| Автор (`frontend_writer`) | `gpt-6-luna / low` | Готовит сообщения коммитов и описания MR |

Архитектор выбирает исполнителя сразу по сложности. Рутинная задача не обязана проходить все уровни. Багфиксер подключается для устранения дефектов; результаты проверяет независимый ревьюер.

## Требования

- Codex с поддержкой пользовательских агентов, навыков, MCP и lifecycle hooks.
- Доступ к моделям из таблицы. Доступность зависит от аккаунта и клиента; установщик её не проверяет.
- Python 3.11 или новее; сторонние Python-пакеты не нужны.
- Node.js 22 или новее и `npx` в PATH. Node нужен хуку и проверкам flow; npx — Playwright MCP.
- Для UI-проверок: запускаемый проект, его зависимости, доступные браузер и безопасные тестовые данные.

## Установка

Клонируйте репозиторий:

```sh
git clone https://github.com/alekseiTurl/frontend-flow.git
cd frontend-flow
```

В Windows используйте `python` или `py -3`; на macOS/Linux обычно `python3`. В примерах ниже используется `python`.

Посмотрите запланированные изменения:

```sh
python scripts/install.py --dry-run --configure-playwright
```

Установите:

```sh
python scripts/install.py --configure-playwright
```

Каталог назначения — `CODEX_HOME`, если он задан, иначе `~/.codex`. Для другого каталога:

```sh
python scripts/install.py --codex-home "/path/to/.codex" --configure-playwright
```

Установщик копирует агентов и оба навыка, добавляет хук в `hooks.json` и формирует команду с абсолютным путём для этого компьютера. Существующие сторонние хуки и настройки сохраняются. Совпадающие файлы не переписываются. При конфликте файлов комплект останавливается до записи; после проверки различий разрешите обновление:

```sh
python scripts/install.py --overwrite --configure-playwright
```

Изменяемые существующие файлы сохраняются в `<CODEX_HOME>/frontend-flow-backups/<timestamp>/`. Не публикуйте эту папку: резервные копии конфигурации могут содержать личные настройки. Для отката закройте активные задачи и восстановите нужные файлы из соответствующей копии. Новые файлы без предыдущей версии в резервную копию не входят.

Флаг `--configure-playwright` добавляет пример конфигурации только при отсутствии `mcp_servers.playwright`. Существующий сервер сохраняется без изменений. Без этого флага настройте сервер по [примеру](config/playwright.toml) вручную. Пример использует `@playwright/mcp@latest`; для воспроизводимого окружения зафиксируйте проверенную вами версию пакета.

Откройте Codex, просмотрите и разрешите новый хук через `/hooks` в CLI, затем начните новый чат. Установщик не меняет доверие к хукам, sandbox или разрешения. Если найден другой хук frontend-flow, объедините определения вручную, чтобы избежать двойного запуска. Официальные сведения: [hooks](https://learn.chatgpt.com/docs/hooks), [пользовательские агенты](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Установка не запускает MCP-сервер и не загружает браузеры. При первом UI-задании проверьте доступность инструментов Playwright MCP в Codex. Если сервер, браузер или приложение недоступны, flow честно отмечает проверку как `blocked`.

## Правила ответов

Краткие ответы на русском уже включены во все роли flow. Если хотите применять эти правила ко всем задачам Codex, используйте:

```sh
python scripts/install.py --install-style
```

Установщик добавляет отдельный отмеченный блок в пользовательский `AGENTS.md` и сохраняет остальные инструкции. [Исходный текст правил](instructions/AGENTS.md).

## Использование

```text
@FF Добавь фильтрацию товаров. Критерии готовности: ...
@FF Исправь баг: [шаги]. Ожидаю: [результат]. Сейчас: [ошибка].
@FF Продолжи сохранённую задачу по фильтрации.
@FW Подготовь сообщение коммита и описание MR по текущим изменениям.
```

Навык требует согласования конкретного плана перед изменением кода. Проверки UI обязательны при изменении интерфейса. Багфиксер не закрывает собственные замечания. Коммиты, push, публикация MR и deploy выполняются только при соответствующем поручении пользователя.

Перед подтверждением завершения координатор показывает полные тексты writer в чате. После успешного `check-done` план удаляется; остальные служебные файлы очищаются после подтверждения завершения. Не используйте служебный каталог flow для хранения единственной копии пользовательских результатов.

## Настройка и разработка комплекта

- Модели, effort и состав встроенных инструкций: [agents/roles.json](agents/roles.json).
- Правила процесса: [skills/frontend-flow/SKILL.md](skills/frontend-flow/SKILL.md).
- Общие и ролевые инструкции: [references](skills/frontend-flow/references).
- После изменения ролей выполните `python scripts/generate_agents.py`.
- При смене моделей обновите таблицы в `SKILL.md`, этой инструкции и `docs/frontend-flow.md`, а также заголовки/маршрутизацию ролевых references.
- Системный навык Codex `skill-creator` нужен только для дальнейшего редактирования навыков через Codex; он не является runtime-зависимостью flow и не копируется в этот комплект.
- Новая модель не подменяется автоматически, если недоступна. Выберите доступную модель и явно обновите конфигурацию.

Проверки:

```sh
python scripts/generate_agents.py --check
python scripts/validate.py
python -m unittest discover -s tests -p "test_*.py" -v
node --test tests/flow.test.cjs
```

Тесты используют временные каталоги и не устанавливают комплект в вашу рабочую конфигурацию Codex.

В репозиторий не входят учётные данные, история чатов, состояние задач, пользовательский `config.toml` или сохранённое доверие к хукам. Сведения об использованных подходах — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
